# gentle-herdr: Herdr visuals as a separate Pi package

Repo `MarsSall/gentle-herdr` (public), local `~/Work/gentle-herdr`, branch `main`. Installed with `pi install git:github.com/MarsSall/gentle-herdr`.
Ports the unmerged part of the old Herdr visuals chain (reference checkout: `/home/mars/Work/Contribuciones/Pi/herdr/worktrees/visuals-split`, branch `ref/herdr-visuals-split`) into a standalone package with its own `/gentle:herdr` command.

## Specs

- S1 — Scope (user, verbatim): "Todo lo de la cadena original" and "ojo, no agregues a la extension lo que ya mergio alan a main que hicimos es solo lo que no metimos en gentle-shell". Excluded because gentle-shell main already ships them: task-summary preference and publisher (`lib/herdr-task-summary-policy.ts`, `lib/herdr-activity.ts`, `extensions/gentle-herdr-activity.ts`), the Layout `Task summary: on/off` choice, and the agent-status file. The package never publishes activity, never writes `herdr-task-summary.json`, and offers no task-summary on/off control.
- S2 — Entry point (user, verbatim): "para entonces nos conviene un comanto que sea gentle:herdr y listo, es enombre del repo me sirve, va a ser publico". The package registers `/gentle:herdr` with its own interactive menu; no change to gentle-shell is required.
- S3 — Distribution (user, verbatim): "Repo propio, pero es necesario un paquete npm?" Answer: no npm publish needed; a valid Pi package installable from git. `package.json` declares `pi.extensions`, keyword `pi-package`, host packages (`@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, `@earendil-works/pi-ai`, `typebox`) only as `peerDependencies` `"*"`, MIT license crediting the original gentle-shell contribution.
- S4 — Features, from the approved issue Gentleman-Programming/gentle-shell#2392 (original text, verbatim): "**Theme**: any native Herdr theme, or **Default**, which mirrors the Gentleman.Dots Herdr profiles: the `one-dark` base, Herdr's text colors (including the sidebar's secondary text) from the live Gentle palette, and the profile values the palette does not define (Gentleman-Cute and Gentleman-Sexy: black panel and the profile's surfaces; neutral Gentle: its panel color). Status and notification colors stay with the base theme." and "**Task summary**: [...] their color." and "When the Theme is **Default**, changing the Gentle Shell theme (Themes or a profile) re-applies the Herdr projection automatically, with the same guards."
- S5 — Apply flow and safety rules (#2392, verbatim): "Confirming saves the preference first, then applies it to the local Herdr client config and requests `herdr server reload-config`." "Edits only Gentle-owned, hash-stamped blocks and the recognized `theme.name` and `$summary` styles; never rewrites user `[theme.custom]` colors, whether hex, named or `reset` (Herdr layers them over any base theme)." "Preserves comments, ordering and LF/CRLF/mixed line endings; ambiguous or unsupported TOML fails closed without writing." "Local client only: SSH/remote panes, child sessions and `herdr-dev` builds are refused before any config access. Herdr clients read theme and sidebar from their own local config even when viewing an SSH machine, so over SSH the menu says so before Enter instead of only reporting \"not applied\" afterwards." "Windows: `%APPDATA%\\herdr\\config.toml` (or `HERDR_CONFIG_PATH`) via a fixed PowerShell helper on NTFS with protected staging and `File.Replace`; if the replacement fails midway, the original is restored."
- S6 — Preferences: the package's own versioned JSON store (`theme`, `summaryColor`) at `<getAgentDir()>/gentle-herdr.json` (Pi SDK public export), validated, bounded read, atomic 0600 write, malformed/unreadable stores refused without overwrite. No import of gentle-shell internals (`agent-home`, `visual-customize-view`, policy modules); small helpers (e.g. Herdr pane detection) are copied with attribution.
- S7 — Summary rows: applying ensures the `$summary`/`$summary2` rows exist in Herdr's sidebar layout (owned block) with the chosen color; the menu also offers removing the package-owned blocks from Herdr's config. The published text and its visibility stay owned by gentle-shell.
- S8 — Default theme re-apply: while the Theme preference is `default`, the package detects a change of the active Pi theme (no core event; observe `ctx.ui.theme`) and re-applies the projection with the S5 guards, at most once per change.
- S9 — Docs: README with install, usage of `/gentle:herdr`, what is and is not edited, Windows/SSH notes, uninstall; tests runnable with `npm test` (node --test, strip-types).
- S10 — Menu clarity and preview (user, verbatim): "lo unico que no me gusta es que no te muestra una preview de como va a quedar y que no te aclara que el default sigue el tema de gentle-shell". Chosen option (verbatim): "bien vamos con la 1" (preview only what is known; no embedded Herdr palettes). (a) Everywhere Default appears (main menu entry and theme list) it says it follows the active Gentle Shell theme and names it, e.g. `Default (follows your Gentle Shell theme: Gentleman-Cute)`. (b) Theme and Summary color lists show a preview that updates as the highlight moves, drawn with the real colors: for Default, a mock Herdr sidebar from the live Gentle palette projection (agent row, secondary text, both summary rows in the saved summary color, panel background when the projection defines one); for a summary color, both summary rows in that color with the saved theme's projection when it is Default. (c) Native Herdr themes show their name and that they look like Herdr's built-in theme of that name; no colors are invented. Highlighting never saves or applies; Enter still asks for confirmation as today.
- S11 — Gentleman-Sexy distinct in Herdr (user, verbatim): "esperaba que hubiera otro color ademas del cute" and chosen option "2". Default under Gentleman-Sexy keeps Cute's Dots surfaces but sets `subtext0` `#FF4F9A` (unfocused session/workspace names, fuchsia), `overlay0` and `mauve` `#B99AA9` (branches, unfocused and focused, grayish pink); focused names keep `text` and `active_row_bg`/`selection_bg` `#2E0F1F`; Cute and neutral Gentle are unchanged.
- S12 — Configure saved machines from the client (user, verbatim): "si pero para, me gustraria que podamso configurar \"ambas\" maquinas desde la extension" and "si la A, pero podriamos poner temas diferentes a distintas maquinas?". Evidence (L12): pane borders of a session are drawn by the Herdr server of the machine where it runs, from that machine's config; sidebar, menus and theme of the UI come from the client. Behavior, from a local client session only:
  (a) a **Machines** entry lists enabled saved machines from `herdr machine list --json` (fields `id`, `label`, `target`, `enabled`; no credentials). Each machine has a theme preference: `same` (default, "Same as this computer") or its own choice (`default` or a native Herdr theme). Preferences store gains `machines: { <id>: { theme } }` with a schema bump that still reads v1 stores.
  (b) Applying (from the main menu, after a theme change, and from Machines) also applies to each enabled saved machine: SSH to `target` non-interactively (`BatchMode=yes`, connect timeout, never prompts for passwords or host keys), resolve the remote config path (`$HERDR_CONFIG_PATH`, else `${XDG_CONFIG_HOME:-$HOME/.config}/herdr/config.toml`), read it with a size bound, plan locally with the same planner and S5 rules (owned blocks only, user `[theme.custom]` untouched, fail closed on ambiguous TOML), write back using private sibling staging and a no-overwrite hard-link commit: atomically move the current config aside (or note absence), verify the aside copy's SHA-256/expected absence, restore on mismatch with a no-overwrite hard link, and commit with a staged-file hard link that fails if another path appeared (keep that external file and retain the displaced original as a sibling backup, reporting only its basename); preserve the original mode and remove staging/aside names after success, with a brief absent-path window and no guarantee against a writer holding the old file open and writing in place after the hash check, then run `herdr --machine <label> server reload-config` only when it changed. Remote Windows servers and machines that fail (unreachable, auth needed, conflict, unsupported) are reported per machine without affecting the others or the local apply. No secrets or file contents are logged.
  (c) The Default theme re-apply (S8) also re-applies machines whose effective theme is Default; failures there produce at most one notice per change.
  (d) In a remote session (SSH guard) the menu explains that this machine's pane borders are configured from `/gentle:herdr` → Machines on the client; it still applies nothing locally.
